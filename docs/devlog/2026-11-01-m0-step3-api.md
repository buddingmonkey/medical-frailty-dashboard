## Goal

Create `apps/api`: a Hono Worker that serves the Vue build with single-page-app fallback,
`GET /api/public/health`, and security headers on every response.

## What happened

2. The AI read the API, caching, site-gate, headers and deployment sections, checked versions
   on npm and Cloudflare's docs, and proposed a plan with three questions.
3. The project lead said yes to all three: run the Worker first for every request until launch,

4. The AI wrote the Worker, generated binding types with `wrangler types`, and added root

   API path and a JS asset. All returned the right status and all 7 headers it checked for. It
   also loaded the page in headless Chrome in light and dark mode: no CSP violations, and the
   self-hosted fonts loaded.
6. The AI updated `architecture.md`, `security.md`, `deployment.md` ("Going live" now has the
   step that moves `/assets/*` off the Worker), `status.md` and the talk notes.

## Decisions

| Decision | Why | Who decided |
| --- | --- | --- |
| `run_worker_first: true` until launch | One place sets headers; the step 5 site gate must cover static files. About 6–8 Worker requests per page view, free at admin-only traffic | Project lead (AI recommended) |
| At go-live, serve `/assets/*` directly with a `_headers` file | Cuts Worker requests to about 1 per page view | Project lead (AI recommended) |
| No `'unsafe-inline'` in `style-src` | Vue's style bindings go through the DOM, which CSP allows; verified in headless Chrome | Project lead (AI recommended) |
| Workers Logs + Traces on, query strings redacted | Free (200k log events a day); search terms stay out of logs | Project lead (AI recommended) |
| Hono's built-in `secureHeaders` instead of hand-written headers | Less code to get wrong | AI |
| `wrangler types` instead of `@cloudflare/workers-types` | Cloudflare's current advice; types match the configured runtime | AI |
| Pin hono 4.13.14 | 4.13.15 and 4.13.16 were under 3 days old | AI, per the rule |

## Corrections and surprises

- **The docs contradicted each other**: "static asset requests do not run the Worker" vs.
  "security headers set by middleware on every response". Found while planning. Cloudflare's
  docs confirm that a `_headers` file does not apply to Worker responses and Worker middleware
  does not see direct asset hits, so a choice was needed.
- **The CSP exception was based on a wrong assumption.** The plan kept `style-src
  'unsafe-inline'` "for Vue's dynamic style bindings", but Vue sets styles through the DOM, which
  CSP does not block. The page renders with the strict policy.
- **Wrangler's generated types made `ENVIRONMENT` a literal union** (`"preview" | "production"`)
  that left out `"development"`. `--strict-vars=false` types it as a string.
- **The AI killed its own shell twice** while stopping the dev server: `pkill -f "wrangler dev"`
  matched the shell command that contained the same text. The fix was killing by process ID.
  No harm done, but a good reminder that cleanup commands need care too.

## What a non-technical builder should take from this

1. Before building, ask the AI what in the plan looks wrong. Here it found two docs that
   contradicted each other, and a security exception that wasn't needed.
2. "Free tier" depends on configuration. Running the Worker on every file is free for a few
   admins but would use up the daily quota at real traffic, so the go-live checklist now says
   when to change it.
