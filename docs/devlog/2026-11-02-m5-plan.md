# 2026-11-02: M5 plan, comparing many states

**Milestone:** M5 planning  •  **People:** project lead (asked for the change, chose the options)
•  **AI:** Claude Code, Opus main session; one research agent on Fable

Start 16:03 CST, end 16:29 CST (`date`).

## Goal
The project lead: the M4 compare page "will not scale to 50 states". Add admin-created unified
categories between the federal ones and each state's own, research how to show many-state
comparisons, and mock it up.

## What happened
1. A research agent (Fable) reviewed visualization research, UX guidance, state-policy sites and
   crosswalk practice (about 30 sources, below).
2. An interactive mockup with simulated numbers: the three category levels and five views
   (https://claude.ai/artifact/CNrREiYvQSpfgNvcnR9VAz, private to the project lead). The
   project lead asked for all five views.
3. Decisions (below), then M5 written into `docs/roadmap.md`; code search moved to M6, admin
   completion to M7, launch to M8 (forward references renumbered; devlog entries keep the
   numbers they were written with).

## Key findings
- One column per state is juxtaposition and does not scale. People comparing many items scan
  everything, pick a subset, or read a summary; the site needs all three (Gleicher 2018).
- Overview first, zoom and filter, details on demand (Shneiderman 1996; Munzner 2014).
- A reorderable matrix suits about 50 entities by 20–40 groups (Bertin; Behrisch et al. 2016;
  Perin et al. 2014).
- Each state's list is a set: show how many states list each code, sorted; UpSet's practical
  limit is about 40–50 sets (Lex et al. 2014; Alsallakh et al. 2016).
- Comparison tables work for 3–4 items; with more, filter and "show only differences"
  (Nielsen Norman Group).
- Crosswalks: SKOS match types, one-to-many mappings, keep the original, version, never delete
  (W3C SKOS; OHDSI). AHRQ's CCSR groups 70,000+ ICD-10-CM codes into ~530 categories.

## Decisions
| Decision | Why | Who decided |
| --- | --- | --- |
| Three category levels: federal, unified (admin-curated), state-specific | Lets different states' categories be compared with each other | Project lead |
| All five views from the mockup | "All of them are useful" | Project lead |
| M5 before code search | Search reuses the drill-down's per-code matching | Project lead (AI recommended) |
| CCSR from the start | Suggests mappings and shows where a state's label and its codes disagree | Project lead |
| CCSR downloaded from AHRQ at load time, pinned by version and hash, never committed; cited in AHRQ's format | AHRQ states no licence for the files; the repo is public | AI |
| One admin may approve a mapping; public pages say who reviewed it and when | Two-person review needs both admins active; can be switched on later | Project lead (AI recommended) |

## What a non-technical builder should take from this

  project lead chose among concrete views instead of describing them in the abstract.
