## Goal
Load AHRQ's CCSR for ICD-10-CM (v2026.1) so unified categories can be built from clinical
groups and so codes no state lists can be shown.

## What happened
1. Builder, test first: parser for AHRQ's CSV (single-quoted codes, 6 category slots, inpatient
   and outpatient defaults), prefix compression, migration `0008_ref_ccsr` (`ref_ccsr`
   `WITHOUT ROWID` with a guard test, `ref_ccsr_categories`), 15 chunks in the existing loader,
   and a `ccsr-coverage` command. Shared longest-prefix lookup in `@mfcd/shared/ccsr`.
2. Licence: the ZIP is downloaded and pinned by SHA-256, never committed; fixtures are synthetic
   rows in AHRQ's layout; the guide in the ZIP has no licence wording.
3. Rows: 87,705 code-to-group rows compress to 66,209 (only 25%: injury codes differ by the 7th
   character). One day's remote budget covers it.
4. Coverage of the four seed states: every valid ICD-10-CM code finds CCSR groups, 321 header
   codes only through "the codes under it" (an API-step rule). 16 listed codes are not ICD-10-CM
   FY2027 codes; recorded in `docs/sources.md`.
5. Deliberate break: trying prefixes shortest-first failed the lookup test.

## Decisions
| Decision | Why | Who decided |
| --- | --- | --- |
| Store the inpatient default only | The views use every group a code has; the default matters only for charts that need one group per code. Revisit if needed | AI (builder), accepted in review |
| A shared helper for header codes ("the groups of the codes under it") comes with the API steps | Needed by the coverage summary (step 4); no caller yet | AI |

## Corrections and surprises
- Importing the shared index from the reference-data CLI broke under Node type stripping
  (`compare.ts` uses parameter properties); the CCSR helpers are a separate import-free export.
- 1,611 old codes in CCSR have longer codes under them (`B880` beside `B8801`), so stored keys
  can nest; the lookup still returns each code's own groups (full-file round trip).
