# 2026-11-01: Planning the site

**Milestone:** before M0 (planning only, no code)  •  **People:** project lead  •
**AI:** Claude Code. Main session on Opus; one research agent on Opus (court ruling); one
web-search agent on Sonnet (Louisiana spreadsheet).

## Goal

Turn a one-page design wiki (`docs/MedicalFrailtyCode-design-wiki.md`) into a full plan:
`CLAUDE.md`, architecture, data model, ingestion, security, testing, low-cost deployment and a
roadmap. The project lead asked for questions instead of guesses and said "no code yet".

## What happened

1. The project lead shared the design wiki, an example `CLAUDE.md` from another project (a
   short file that points to docs), and sample code lists from four states (GA, LA, MT, NE),
   some as links and some as downloaded PDFs.
2. The AI extracted text from every PDF (`pdftotext`) and profiled the data before planning:
   columns, row counts, category names and code formats. This surfaced problems that the
   design wiki did not mention: codes with and without dots, wildcards (`C34.x`), ranges cut
   off by the PDF layout, and CPT ranges written as prose (`33230 and 33240`).
3. The AI asked two rounds of multiple-choice questions: hosting, where to parse files, how
   AI cleanup should work, admin login, CPT copyright, public vs private repo, domain.
4. While the AI was writing, the project lead added two requirements mid-stream:
   - the whole site must stay private until it is marked live;
   - states will reissue their lists, so a re-upload must replace a whole state safely, with
     checks so a wrong file cannot damage the database.
   Both became core parts of the design (site gate; draft → checks → publish → rollback).
5. The AI wrote `CLAUDE.md` and eight docs in `docs/`.
6. The project lead answered the open questions. Two answers needed checking (see below), so
   the AI started a research agent and a search agent in the background.
7. Results came back; the plan was updated. The project lead chose to show each state's own
   qualification rule, and noted that a team of lawyers may change that later.
8. Added: an admin "watch dates" page for legal and policy deadlines, and this devlog,
   playbook and talk notes.

## Decisions

| Decision | Why | Who decided |

| Launch gate: 2 fully mapped states + a usability test with real users | Usefulness and correct use matter more than state count | Project lead |

## Corrections and surprises

- **A pasted explanation was wrong.** The project lead pasted an explanation of Louisiana's
  "Code Designation" column (0 = diagnosis, 1 = procedure, 2 = other). The AI checked it
  against the data before accepting it: diagnosis codes appear with all three values, so the
  explanation could not be right. A later source (SHVS, 2026-09-11) supported a different
  meaning (qualifies alone / needs a supporting code / supporting evidence), which fits the
  data. It is still labeled "inferred" until the state confirms it.
- **A legal premise was only partly right.** The project lead understood that a recent court
  ruling struck down the "tier" approach, so all tiers qualify. The research agent found and
  the main session verified the opinion (*Massachusetts v. Oz*, D. Mass., 2026-10-29): it
  struck down a different federal test and never mentions tiers; Georgia's own page still
  says its second list only counts in combination. The project lead changed the decision and
  noted that the legal team has the final word.
- **The AI checked the research agent too.** Because the research contradicted the project
  lead, the main session re-downloaded the court opinion and Georgia's page and confirmed the
  key quotes itself before reporting.
- **Louisiana publishes only a PDF printout of a spreadsheet.** A search agent confirmed no
  spreadsheet is public, so the importer has to handle that PDF.

## What a non-technical builder should take from this

1. Give the AI your real source files early. Profiling actual data found problems that a
   written spec could not.
2. When the AI or a pasted answer states a fact, ask it to check that fact against the data or
   a primary source. Both humans and AI were wrong once in this session, and checking caught it.
3. You can add requirements mid-stream. Say them plainly; the plan absorbed both.
