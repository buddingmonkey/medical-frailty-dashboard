# 2026-11-01: M1 step 2, code normalization

**Milestone:** M1 step 2  •  **People:** project lead  •  **AI:** Claude Code, Opus main session
(no builder agent)

Start 21:18 CST, end 21:33 CST (from the PC clock).

## Goal
`packages/shared/src/codes.ts`: split a state's code cell into codes, wildcards and ranges,
normalize them, infer the code system, and build code page URLs, with a test row for every
pattern in the state files.

## What happened
1. Before planning, the AI extracted every code from the two seed files on this computer (LA:
   2,117 codes; GA Attachment A: 1,684) and grouped them by shape. That found patterns the docs
   did not list: wildcards after any position (`S06.2*`), ranges of bare categories
   (`D80-D83`), a range with one wildcard (`M30-M31.*`), and 67 LA pharmacy rows with
   3-character drug class codes (`H2G`) shaped exactly like ICD-10-CM categories.
2. The project lead approved the plan, with one condition on undotted ICD codes: a code must
   still match across states that write dots differently. It does: `code_norm` drops the dots,
   and a test shows NE `A0103` and `A01.03` give the same value.
3. **The project lead changed the process:** move through the steps without waiting for
   approval, merge on green CI, stop only at the end of a milestone (`docs/status.md`, "How
   the user likes to work").
4. The AI wrote 103 table-driven tests, then the code. They passed on the first run, so the
   AI broke two rules on purpose (truncated ranges, placeholder X) and saw 2 and 4 failures
   before restoring the code.
5. Added code system `drug_class` and regenerated `0000_init` (no remote database has applied
   it yet). The local safety check blocked an `rm` with a glob after `cd`; the AI reran it
   with explicit file paths.

## Decisions
| Decision | Why | Who decided |
| --- | --- | --- |
| New code system `drug_class`, set only from the source | `H2G` would otherwise be stored as an ICD-10-CM category | Project lead, on AI recommendation |
| Per-source `undottedIcd` setting (NE on) | Flagging every undotted HCPCS code would flag 481 LA rows for nothing | Project lead (on condition that cross-state matching still works) |
| Bare categories and category ranges: `includes_children = null`, flagged | The state may mean the code alone or the whole category | Project lead, on AI recommendation |
| `entryCovers` built now | Pins down what a range means while ranges are being defined | Project lead |
| No NDC parsing yet | No seed state publishes NDCs | Project lead |
| Work through steps without approval; stop at milestone ends | Approval on every step was slowing the work | Project lead |

## Corrections and surprises
- **The docs had missed real patterns.** Profiling the real files, not the docs' summary,
  found six new code shapes, one of which (drug class codes) would have been stored silently
  in the wrong code system.
- **Green on the first run proves little.** All 103 tests passed at once; deliberate breakage
  showed they can fail.
- **Licensing question for the legal team:** the drug class codes look like First Databank's
  licensed HIC3 classes. Added to the legal review list; we show only the state's own text.
- **Lesson for later migrations:** changing a CHECK constraint makes drizzle-kit rebuild the
  table, which drops the search triggers without warning. Written down in
  `docs/deployment.md`.

## What a non-technical builder should take from this
- Have the AI count the real data by shape before writing rules. Summaries written by people
  (or by an AI earlier) leave things out.
- When you hand the AI more freedom, say where the hard stop is. Here, it is the end of each
  milestone.
