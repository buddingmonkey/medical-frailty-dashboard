# 2026-11-17: Cutting the UI text

**Milestone:** M8 (pre-launch polish)  •  **People:** project lead  •
**AI:** Claude Code, Opus main session; one adversarial reviewer agent; three builder agents in
worktrees

## Goal
The site had far too much text, worst on the admin screens. Review it against content-design
practice, then cut and re-lay it out, keeping the disclaimers short but present.

## What happened
1. The project lead asked for "an antagonistic reviewer" to compare the site with design best
   practice and cut the "overly verbose text that agents inject into design".
2. A reviewer agent read every page's source (it did not run the site) and wrote a report:
   about 5,600 words of static text on the admin screens (1,900 of them in 65 tooltips) and
   about 1,900 on the public pages, outside About and the policy pages. The sentences were
   mostly plain. The faults were repetition ("Audit log" 13 times; one federal-category rule
   explained five times on one screen), a hint and a tooltip on the same field, and
   first-use how-to on screens the team uses every day.
3. The lead proposed doing the admin screens first and sending the public wording to legal
   first. The project lead said to do all of it: none of the old wording had been vetted by
   lawyers either, so apply the new text and mark it in `docs/legal-review.md` for sign-off.
4. Three builders ran in parallel on separate files: the admin workflow screens (nav grouped,
   Overview turned into a per-state status board, how-to moved to the Guide), the admin
   category and mapping screens, and the public pages plus `docs/legal-review.md`.
5. The lead merged the three branches, put back "excluded from" in the home intro (a builder
   had written "exempt"; the statute's term is "specified excluded individuals"), fixed a
   stale Guide line about (i) buttons, and added the house style to `docs/playbook.md`.
6. `pnpm check:full` found three admin e2e tests that looked for the old layout (a status
   sentence that is now a badge, a panel that is now a closed disclosure, a reworded tooltip).
   The tests were updated; all 287 pass.

## Decisions
| Decision | Why | Who decided |
| --- | --- | --- |
| Rewrite the public and disclaimer wording now; legal signs off afterwards | The old wording was never vetted either; legal can add text back | Project lead |
| Keep the AMA notice, the code page's CPT note and the CPT rule unchanged | Licence terms, not padding | Lead |
| Keep "excluded from", not "exempt from" | Matches the statute's term | Lead |
| A 10-rule house style for UI text, in the playbook | So later builders don't add the padding back | Lead, from the review |

## Corrections and surprises
- A builder flagged that a tooltip inside a table header might add "About entries" to the
  column's name. A test showed the name is just "Entries", so nothing changed; the test stays.
- The builders updated unit tests but could not run e2e (port clashes), so three browser
  tests broke at the merge. All three asserted old wording or structure, not behaviour.

## What a non-technical builder should take from this
- AI-written screens drift toward explaining everything everywhere. Ask a reviewer to count
  words per screen and find repeats; the counts make the problem obvious.
- Before changing wording on a legal topic, check the law's own term. A shorter synonym can
  change the meaning.

## Numbers

- Public pages: home 210 → 130, state page 260 → 150, compare intros and notes 900 → 500,
