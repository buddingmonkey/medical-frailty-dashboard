## Goal
Read .xlsx files, after the project lead chose "a smaller xlsx library" from npm over SheetJS
from its CDN.

## What happened
1. Compared on the npm registry: `exceljs` 4.4.0 (21.8 MB unpacked, Node-oriented
   dependencies such as `archiver` and `tmp`) and `read-excel-file` 9.3.14 (MIT, 2.5 MB,
   published 2026-10-29, so past the 3-day rule; depends on `fflate`, `saxen` and two small
   packages by the same author). Picked `read-excel-file`; `pnpm audit` clean.
2. Its `/web-worker` build is for code already in a Web Worker (ours), so it starts none.
3. Fixture: no openpyxl here, so `fixtures/make-sample-xlsx.py` writes a 5 KB two-sheet
   workbook with the standard library (an .xlsx is a zip of XML): LA and MT headers, a number
   cell, inline and shared strings, a blank row. Committed with its script.
4. Tests first: both sheets read, `0` stays `"0"`, locators `LA row 4` count the blank row,
   a fake .xlsx is refused. Red against the old "not set up yet" error, then green.
5. Hands-on: the workbook through the real Worker in `pnpm dev`, sheet picker switches tables,
   axe clean, no console errors. Worker bundle: 158 KB, loaded only when a file is parsed.

## Decisions
| Decision | Why | Who decided |
| --- | --- | --- |
| `read-excel-file` instead of SheetJS | Stays on the npm registry; small; maintained | Project lead (library family), AI (which package) |
| Numbers kept as cell text | Codes and designations (`0`, `0450` stored as text) must not change shape | AI |
