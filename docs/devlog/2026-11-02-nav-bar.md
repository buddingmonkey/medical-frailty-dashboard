# 2026-11-02: main navigation and the All states page

**Milestone:** between M4 and M5 (project lead's request)  •  **People:** project lead (asked
for header navigation; chose "a proper nav bar")  •  **AI:** Claude Code, Opus main session

Start 15:47 CST, end 15:54 CST (`date`).

## Goal
Links to every public page in the header: a clear nav bar with the current page marked, a menu
button on phones.

## What happened
1. One list of nav links in `packages/shared/src/public.ts` (`siteNav`, `siteNavCurrent`), used
   by the Vue header and the server-rendered HTML. A page joins the list only when it exists
   (Search in M5, About in M7), so no link can 404.
2. Tests first (3 component), then `components/SiteNav.vue`: a second header row on wide
   screens; on phones a "Menu" button (`aria-expanded`, `aria-controls`, Escape closes and
   returns focus, any navigation closes it). The current page gets `aria-current="page"`; a
   deeper page of a section (`/states/ga`) marks its section with `aria-current="true"`.
3. "States" needed a page: `/states` lists every state and DC (the home page's table), in Vue
   and server-rendered, and in the sitemap. The state page's "All states" link now goes there.
4. Every server-rendered page carries the same nav (`navHtml`), so crawlers and no-JavaScript
   readers get the links too.
5. e2e (3): the nav bar through every page; on a phone, the menu in light and dark with axe.
6. Deliberate break: removing `aria-current` failed the component test.
7. Screenshots: desktop (state page, "States" marked) and phone (dark, menu open).

## Decisions
| Decision | Why | Who decided |
| --- | --- | --- |
| A nav bar as a second header row; a menu button on phones | The project lead's choice of the options shown | Project lead |
| Add a `/states` page rather than link "States" to the home page | A nav item that goes to the same page as "Home" is confusing | AI |
| No links to Search or About until those pages exist | A link must never 404 | AI |
