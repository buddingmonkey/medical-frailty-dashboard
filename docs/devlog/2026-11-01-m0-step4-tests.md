# 2026-11-01: M0 step 4, test harness and theme menu

**Session:** 2026-11-01 16:41–16:55 CST  •  **Milestone:** M0 step 4  •  **People:** project lead  •
**AI:** Claude Code, Opus main session, no subagents

## Goal

Set up every test layer with one real passing test each (unit, component, API, E2E +
accessibility), and a `pnpm check` that prints one line per stage. The component test is the
theme switch planned in step 2.

## What happened

1. The project lead merged PR #3 and asked to continue.
2. The AI checked versions and proposed a plan. It reported that the Workers test pool only
   supported Vitest 4 and bundled an older runtime, and recommended lowering the Worker's
   compatibility date to 2026-08-15 to match. It also proposed a text-only theme switch.
3. The project lead approved lowering the date, and asked for a **dropdown with icons** in the
   header.
4. During install, pnpm warned that `@cloudflare/vitest-pool-workers` is deprecated: it was
   renamed `@cloudflare/vitest-plugin`. The new package supports Vitest 5 and bundles the same
   runtime as our wrangler. The AI switched to it, moved to Vitest 5, and put the compatibility
   date back to 2026-10-23, so the approved change was no longer needed.
5. Tests first, at every layer: the AI wrote each test, saw it fail (3 unit, 5 API, 6 component
   failures), then wrote the code. New code: a zod `healthResponseSchema` in `packages/shared`,
   a 405 guard for non-GET public API calls, and the `ThemeMenu` component.
6. The AI added Playwright with axe, and `scripts/check.ts` for `pnpm check` and
   `pnpm check:full`. Both pass: 3 unit, 6 component, 7 API and 5 E2E tests.
7. To prove the tests can fail, the AI broke things on purpose: an inline style (the CSP
   blocked it and the E2E console check failed), and a request with no mock (MSW refused it).
8. Docs updated: `CLAUDE.md` (test filter command), `testing.md`, `architecture.md`,
   `security.md`, `roadmap.md`, `status.md`, `playbook.md`, talk notes.

## Corrections and surprises

- **The AI's version research missed a rename.** It checked `@cloudflare/vitest-pool-workers`
  but not whether the package was deprecated, and built a recommendation (lower the runtime
  date) on it. The project lead approved it. pnpm's deprecation warning caught it at install
  time, and the change was undone before any commit. Lesson for the AI: check the `deprecated`
  field, not just the newest version.
- **MSW 3 renamed `onUnhandledRequest` to `onUnhandledFrame`.** The old name was silently
  ignored at runtime; only the strict typecheck caught it.
- **`pnpm test -- <filter>` (in `CLAUDE.md`) ignored the filter** and ran every test. The
  working form is `pnpm test <filter>`.
- **Running Vitest from the repo root wrote a stray, empty `src/typed-router.d.ts`** at the
  root, because the router plugin resolved paths from the working directory. Fixed with an
  absolute `root`; found by the lint stage of `pnpm check`.
- **pnpm 12 fails installs on unreviewed install scripts** (`ERR_PNPM_IGNORED_BUILDS`). In step 3
  it looked like a warning; it would have broken CI.
- **The AI killed its own shell a third time** with a cleanup command whose pattern matched its
  own text. No harm. Next time: stop dev servers by process group or by port.

## What a non-technical builder should take from this

1. A yes is based on the facts at the time. If the AI learns something new after you approve,
   it should tell you and undo the change if it is no longer needed. Here it did.
2. Make the AI show a test failing before you trust it passing.
