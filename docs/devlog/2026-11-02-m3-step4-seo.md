## Decisions
| Decision | Why | Who decided |
| --- | --- | --- |
| Downloads at `/states/<st>/codes.csv|json`, not under `/api/` | `robots.txt` disallows `/api/`; crawlers and researchers should be able to fetch the data | AI |
| Every CSV row carries its source title, URL and date | A row copied out of the file keeps its citation | AI |
| Badge labels quoted as written in the summary sentence ("Qualifies alone, 1,489") | The labels are provisional legal wording; bending them into grammar would reword them | AI |
| All 51 state pages in the sitemap, not only states with a list | "Does Alabama have a list?" is a real question; the page answers it | AI |
| No `license` in the `Dataset` JSON-LD yet | A legal decision; added to the legal review list | AI (flag for the legal team) |

## Corrections and surprises
- After a wording change, the e2e run still showed the old sentence twice: the local Worker
  kept its Cache API in the persist folder, and the cache key (data version + web build) did not
  change when only Worker code changed. Production had the same gap for up to 5 minutes after
  a deploy. Fixed both ways: the deployed version id (`CF_VERSION_METADATA`) is now part of
  every public cache key, and the e2e seed bumps `data_version`. A new test fails without it.

## What a non-technical builder should take from this
- Anything cached needs a key that changes whenever what produced it changes: the data, the
  web build and the server code.
